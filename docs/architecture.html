How a message actually moves through the system

Two mechanisms carry everything else: a bounded tool-calling loop that answers ordinary turns, and a four-agent pipeline it can hand the hard ones to. Both run on local models by default; exactly one step reaches outside the machine.

Mechanism 1 — every chat turn

The tool-calling loop

The model never receives the raw chat history once it grows past roughly 4,000 tokens — a compaction gate swaps the old middle for a cached summary first, cutting only at a user-message boundary so a tool round is never split. From there the loop runs until the model stops asking for tools, or six rounds elapse.

Mechanism 2 — the deep_analysis tool

The four-agent pipeline

One of those 22 tools is itself a whole crew. It exists because a single 7B pass is weak at multi-step reasoning — so the work is split into stages, and only the stage that genuinely needs stronger reasoning leaves the machine. Two defences sit around it: file inputs are read in Python before any model sees them, and every stage's output must clear a guardrail before the next stage is allowed to build on it.

State

Everything persists as plain JSON on disk

data/chats/*.json
One file per conversation, full fidelity — searchable, exportable to Markdown. Compaction never edits it.
data/embeddings.json
Document chunks (800 chars, 150 overlap) with vectors. Retrieval fuses cosine and BM25 rankings.
data/memory.json
Durable facts about you. Injected into every system prompt, so no recall call is needed.
data/workspace/
The only directory file tools can touch. Path traversal outside it is rejected.
